## What worked
- Whole skill v1.3 path ran end to end: pricing pre-check → storyboard w/ hook scoring
  (1A=74, 1B=63; A generated) → keyframe chain → assemble → QC, with project.json updated
  per shot and spend.md per batch.
- Keyframe chain (K1) works as designed and **held the character** across 3 chained
  generations (see drift verdict below).
- **Server-side handoff**: `fal-ai/ffmpeg-api/extract-frame` (last frame, ~$0.0007/call)
  replaces local-extract→upload for chaining. Local upload was effectively blocked anyway
  (no FAL_KEY on this box; MCP base64 upload burns ~35k tokens/frame of context). Local
  ffmpeg extraction kept as verification copy. → Candidate skill edit for Step 4.
- Assembly: sidechain ducking (K4), 2-pass loudnorm, SRT burn via `subtitles=` +
  `force_style` worked on Windows/Git Bash. `drawtext` needs explicit `fontfile=` —
  fontconfig has no default config on this box (segfaults without it).
- Audio: MiniMax TTS clean EN read; CassetteAI 35s BGM in ~2s compute (license-safe).

## What failed / drifted
1. **MCP result-fetch 404 on bare t2v endpoint id** (`.../v1/pro/fast`): job completes and
   bills, but the result is unfetchable through the MCP tool (tried 4 param variants).
   $0.104 wasted. **Rule: always submit Seedance t2v via the full
   `.../fast/text-to-video` alias** (i2v full path fetches fine). → skill/config note.
2. **Seedance 1.0 fast outputs SILENT video** — the "native audio" lines the storyboard
   template writes into every video_prompt do nothing on this tier (only Seedance 1.5/2.0
   generate audio). Harmless (we replace audio at assembly) but the template rule
   over-promises; SFX must come from BGM/foley at assembly.
3. **Loudness ceiling**: -14 LUFS exactly not reachable with TP ≤ -1.5 on this mix
   (true peak -1.4); landed -15.9, inside the QC window. Fine for drafts.
4. **720p request returns 704×1248** (not 720×1280) — QC aspect tolerance absorbs it;
   cost math should use actual dims.
5. **Character drift (E4 fold-in)**: chained 1A→2→3→4 kept body/eyes/proportions;
   accessory drift real — antenna went single-wire-red-bead → two antler prongs by
   re-mint 3; bean prop turned cookie-like. **Pure t2v (shot 5, same text) = entirely
   different robot.** Fresh t2i (shot 6) recovered the antenna but shifted head shape.
   Verdicts: keyframe chain ≫ t2v for recurring characters; list accessories explicitly
   ("single copper wire antenna with ONE red bead") in every re-mint prompt; a character
   sheet reference image (assets/characters/) should anchor even chained shots.
